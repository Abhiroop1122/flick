# Security & privacy

Flick is built so that your files and clipboard only ever travel between your own
devices, over your own Wi-Fi.

## What travels where

- **Only your local network.** Phone and computer talk directly over Wi-Fi (or the
  phone's hotspot). There are no Flick servers, no accounts, and no internet
  connection is needed.
- **No analytics or tracking.** Neither app reports anything to anyone.
- **Discovery** sends a small "who's there?" message on your network (UDP port 47474)
  containing the phone's random ID and name; computers answer with their name, port
  and certificate fingerprint. Macs also announce themselves over Bonjour.

## Encryption and identity

- Every computer creates its own TLS certificate (ECDSA P-256) the first time Flick
  runs. All transfers use HTTPS with that certificate.
- The phone only talks to a computer whose certificate matches the SHA-256 fingerprint
  it announced (**certificate pinning**), and remembers it. Someone else on the Wi-Fi
  can't read a transfer or pretend to be your computer. If a computer's certificate
  ever changes, the phone shows **Security error** instead of connecting.
- For a computer added by IP address, the phone trusts the certificate it sees the
  first time and pins it from then on.

## Who can send to whom

- **Phone → computer, unknown phone:** the person at the computer must click
  **Accept** every time, unless they chose *Always accept* for that phone.
- **Connected (paired) phones:** connecting requires a click on the computer. The
  computer then gives the phone a random 256-bit **trust key**; the phone sends it with
  every request and the computer checks it in constant time. Only paired phones can
  receive the computer's clipboard and files, or send their clipboard to it.
- **Undo any time:** *Forget connected phones* on the computer, or *Disconnect* /
  *Forget this computer* on the phone. A forgotten phone is refused and must connect
  again.
- **Computer → phone:** the computer can only reach phones that are connected and
  have their own link open. It never opens connections to the phone.
- The computer's own settings controls (used when you open Flick or right-click
  *Send with Flick*) only answer requests from the same computer that carry a random
  token kept in a file only your user account can read.

## Receiving safely

- Nothing is written to disk until someone accepts (or the phone is trusted).
- File names are reduced to a bare name: folders, `..`, control characters, reserved
  characters and Windows device names (`CON`, `NUL`, …) are removed, so a sender can't
  write outside the save folder.
- Existing files are never overwritten: `photo.jpg` becomes `photo (1).jpg`.
- Files are written to a temporary name and only appear once complete. Cancelled or
  failed transfers are deleted.
- Only `http` and `https` links are ever opened automatically. Other text is just
  copied.
- Sessions expire after two minutes without data.

## Clipboard privacy

- Only text and links, at most 100 KB, and only when it changes.
- **Passwords are never shared.** Clipboard content that password managers mark as
  private is skipped:
  - Windows: `ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`,
    `CanUploadToCloudClipboard = 0`, `CanIncludeInClipboardHistory = 0`
  - Mac: `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`
  - Android: clips marked `IS_SENSITIVE`
- Text that came from a device is never sent back to it.
- Turn sharing off on the phone (two switches) or on the computer (*Share clipboard
  with phones*).

## The automatic-copy helper

Android only lets an app read the clipboard while it's on screen. To send your copies
automatically, Flick has an optional Accessibility service, **Flick — send what I
copy**, which you switch on yourself in Accessibility settings.

- It only reacts to a tap on a Copy button or menu, a "Copied" message, or Android's
  clipboard preview.
- It only reads the clipboard at that moment, and only when sending is on and a
  computer is connected. To read it, Flick shows an invisible one-pixel window for an
  instant; Android announces each read (*"Flick pasted from your clipboard"*).
- It doesn't read, keep or send anything else on your screen, and never reads text
  marked as a password.
- Switch it off any time in Accessibility settings or with *Send what I copy on this
  phone*.

Because the app includes this service, Google Play Protect may block installing Flick
from a file in some countries. See [Install → Android](INSTALL.md#android).

## Permissions

**Android**

| Permission | Why |
|---|---|
| Internet, network and Wi-Fi state, Wi-Fi multicast | Find computers on the Wi-Fi and talk to them |
| Notifications | Transfer progress, files from your computer, the connection notice |
| Foreground service (data sync, connected device) | Keep a transfer or the connection to your computer running in the background |
| Run at start-up | Reconnect to your computers after the phone restarts or Flick updates |
| Ignore battery optimisations (asked) | Stop Android from pausing the connection |
| Storage (Android 8–9 only) | Save files from your computer to Downloads |
| Accessibility (optional, you switch it on) | Automatic copy, see above |

**Mac:** *Local Network* (asked once) so phones can find it; it starts at login through
a standard LaunchAgent.

**Windows:** one administrator prompt to add an inbound firewall rule named **Flick**.
Everything else is installed for your user only.

## What's stored on each device

| Device | Data |
|---|---|
| Phone | Its random ID and name, the computers it knows (name, address, certificate fingerprint, trust key), your settings, and crash details if Flick stopped unexpectedly (only until you copy or dismiss them). |
| Computer | `flick-settings.json` (its ID, name, save folder, settings, connected phones and their trust keys), `flick-tls.crt` / `flick-tls.key` (its certificate), `flick.log`, `agent.json` (local port and token). Mac: `~/Library/Application Support/Flick/`; Windows: `%APPDATA%\Flick\`. |

Received files are only stored where you chose (Downloads by default).

## Reporting a problem

If you find a security problem, please don't post it publicly. Report it privately as
described in the [security policy](../.github/SECURITY.md).
